# Контракт LLM и проверка 0.13.0

Игрок по-прежнему говорит обычным языком. LLM-диспетчер выбирает точные имена адресатов из слышащего экипажа; агент сам интерпретирует приказ и возвращает инструмент с аргументами. Исполнитель проверяет типы, обязательные поля, допустимые значения и границы. Код не превращает текст приказа или реплики модели в угадываемые игровые действия.

Все разрешённые инструменты описываются в каждом решении, независимо от профессии и слов приказа. `allowedTools`, ограничения полного контроля и выключенной памяти сохраняются. Старое `toolSelection` нормализуется в `all`. И системный промпт, и режим директора объясняют аргументы, ожидание задач, следующего хода для справки, ограничения инвентаря, крафта и памяти. В `toolMode="prompt"` передаются полные JSON Schema, включая вложенные схемы планов; ответ должен быть корректным структурированным JSON. Произвольный текст и повреждённые native arguments отклоняются.

## Явные аргументы

| Задача | Вызов модели |
|---|---|
| Найти пустые боеприпасы | `inspect(kind="items", category="ammo", condition="empty")` |
| Найти остаток до 30% | `inspect(kind="items", category="ammo", condition="low")` |
| Найти остаток от 10 до 20% | `inspect(kind="items", category="ammo", min_condition_percent=10, max_condition_percent=20)` |
| Проверить содержимое конкретного шкафа | `inspect(kind="items", from="#123")` |
| Взять два инструмента | `take_item(category="tool", count=2)` |
| Взять отмеченный ящик | `take_item(mark="ai")` |
| Разобрать отмеченное | `deconstruct(mark="deconstruct")` |
| Надеть скафандр | `equip(category="diving_suit")` |
| Убрать предмет в подходящее хранилище | `move_item(item="#123", destination="storage")` |
| Отдать предмет человеку | `move_item(item="#123", destination="character", to="Точное имя")` |
| Загрузить C4 в снаряд | `put_in(item="точный prefab ID C4", into="#123")` |
| Атаковать конкретного врага | `attack(target_type="character", target="[c123]")` |
| Выжечь флору в отсеке | `attack(target_type="ballast_flora", target="Балласт [h123]")` |

В этой таблице ссылки условные: модель должна копировать актуальные ID из наблюдения. `#ID` — экземпляр предмета/машины, `[hID]` — отсек, `[cID]` — персонаж или тело. Категории имеют фиксированные значения: `weapon`, `ammo`, `medical`, `tool`, `diving_gear`, `diving_suit`, `diving_mask`, `oxygen`, `reactor_fuel`, `extinguisher`, `battery`, `material`. `condition="empty"` означает 0%, `low` — до 30% включительно, `used` — меньше 100%; числовые границы включительны.

`item` и `query` содержат буквальное название, prefab ID или точную ссылку. Слова `empty`, `used` внутри названия остаются частью названия. `from` задаёт отдельный источник; имя персонажа означает его инвентарь, а не комнату. Тип переноса задаёт `destination`, тип боевой цели — `target_type`. Поле `item="*"` явно выбирает все совпадения в заданном источнике/категории/пометке. Числа должны быть JSON-числами, флаги — `true`/`false`; строковые числа, неизвестные поля и выход за границы возвращают ошибку.

## Связи машин

Наблюдение `machines` показывает ID, вид, отсек, активность, питание и реальные направленные связи `fromId -> toId`. `inspect(kind="machines", query="#123")` раскрывает вход, выход и содержимое источников. Только `relation="ingredient_source"` означает, что связанный контейнер снабжает этот фабрикатор. `entity_link` сообщает сам факт другой связи. Соседство шкафа с машиной не создаёт связи автоматически; недоступные источники отмечены `accessible=false`.

`inspect(kind="items", linked_to="#123")` ищет ресурсы в фактически связанных источниках. При `craft(item="точный prefab ID", amount=2, machine="#123")` фабрикатор сам забирает подходящие материалы из своего входа и этих источников, включая вложенные контейнеры. Если связан деконструктор, используется его выход. Бот вручную приносит только то, что машине недоступно через такие связи. `amount` — число выходных предметов с округлением до полной партии рецепта. Отчёт изготовления перечисляет реальные ID и места продукции.

## Проверка в игре

1. Проверьте `LlmAgents 0.13.0 loaded` в логе. При обновлении сохраните собственный `llm_config.json` и каталог памяти.
2. Отдайте одинаковые по смыслу приказы на разных языках, без заранее известных формулировок. В логе должны быть `route_message` с точными именами и вызовы с явными полями; исходный приказ передаётся без словарных `Hint`.
3. Найдите три одинаковых ящика с 0%, 20% и 100%. Проверьте `empty`, `low`, диапазон процентов и перенос точного `#ID`. Неизвестное имя/ID не должно заменяться случайной целью.
4. Свяжите шкаф с фабрикатором, а второй такой же шкаф оставьте рядом без связи. В `machines` источником должен стать только связанный. Скрафтите предмет из материалов в связанном шкафу: бот идёт к фабрикатору и использует нативный забор материалов. Повторите с вложенной сумкой, выходом деконструктора и закрытым источником. При отсутствии связи материалы доставляются вручную.
5. Повторите изготовление и выгрузку тяжёлых снарядов, загрузку C4, обыск/перетаскивание тел и быструю смену раунда с заметками из проверки 0.12.0, используя новые явные аргументы.

Автоматические проверки не воспроизводят физику, геометрию лодки и сторонние игровые моды. Эти сценарии требуют отдельного игрового прогона.
