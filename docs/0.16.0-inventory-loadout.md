# 0.16.0: желаемая раскладка инвентаря

ИИ может задать боту постоянную схему «слот → предмет/количество». Бот сам возвращает имеющиеся предметы на заданные места, а отдельный периодический обзор модели позволяет пересматривать схему и планировать получение недостающих вещей. Раскладка относится к собственному инвентарю бота, включая носимые сумки, пояс, оружие и их доступные отделения.

## Инструменты и адреса

1. `inspect_inventory(target="self")` показывает фактические индексы, типы слотов, предметы и их `prefab`. У каждого вложенного инвентаря есть `loadout_path`, который можно скопировать в правило.
2. `set_inventory_loadout` задаёт полную новую схему. Незаданные слоты остаются свободными от правил. При редактировании одного правила нужно передать и остальные сохраняемые правила.
3. `inspect_loadout()` показывает схему, фактическое содержимое каждого заданного слота, совпадения, отсутствующие предметы, причины ожидания и время следующей проверки.

В правилах используются **точные prefab-идентификаторы**, включая модовые. Имена на языке интерфейса, категории и временные `#ID` для постоянной схемы не подходят. Все индексы начинаются с нуля; значения нужно брать из текущего осмотра, поскольку у модовых персонажей и контейнеров они могут отличаться.

Пример формы вызова ниже условный: индексы и prefab надо заменить фактическими из `inspect_inventory`:

```json
{
  "enabled": true,
  "check_interval_seconds": 15,
  "review_interval_seconds": 120,
  "slots": [
    { "slot": 4, "prefab": "wrench", "count": 1 },
    { "slot": 5, "prefab": null },
    {
      "path": [{ "slot": 7, "container_index": 0 }],
      "slot": 0,
      "prefab": "bandage",
      "count": 2
    }
  ]
}
```

- `slot` — место назначения в основном инвентаре или в отделении по `path`.
- `prefab: null` — оставить слот пустым. Для такого правила `count` должен быть 1 или отсутствовать.
- `count` — число отдельных экземпляров в стеке, по умолчанию 1. Фактический предел стека определяется игрой.
- `path` — путь от основного инвентаря через носимые контейнеры. Каждый шаг выбирает предмет в родительском `slot`, затем его компонент `container_index` (по умолчанию 0). Для основного инвентаря путь отсутствует или равен `[]`.
- `enabled: false` приостанавливает автоматическое обслуживание и периодические обзоры ИИ, сохраняя переданные правила. Для отключения с сохранением нужно передать текущий список `slots` целиком. `slots: []` очищает схему.

Пределы: 64 правила, глубина пути 4, количество 1–32, интервал обслуживания 5–300 секунд и обзора ИИ 30–3600 секунд. Слоты экипировки вмещают один предмет. Двуручный предмет — один экземпляр, занимающий несколько мест; разные несовместимые вещи в перекрывающихся слотах отклоняются. Два пути к одному физическому месту не допускаются.

## Автоматическое обслуживание

Локальная проверка по умолчанию выполняется раз в **15 секунд**, без обращения к модели. Она переставляет только уже носимые предметы: заполняет нужные слоты, выравнивает количества, освобождает явно пустые места и безопасно размещает вытесненные вещи. При отсутствии места прежнее содержимое сохраняется, а причина показывается в статусе. Перестановки учитывают слоты экипировки, стеки, вложенность, доступ к контейнерам и резервы других задач.

Автоматическая проверка откладывается во время крафта, лечения, переноса тел, использования предметов, рабочих задач штатного ИИ, опасности, тяжёлого ранения, недостатка кислорода, пребывания снаружи или под водой. При простое, ожидании или обычном перемещении без подзадач получения снаряжения раскладка может обслуживаться. Заданный инструмент или костюм защищён от немедленной уборки штатным ИИ в такой спокойной обстановке; активная работа и выживание сохраняют приоритет.

Автоматическое обслуживание не создаёт предметы и не ходит за запасами. Недостающее отображается в отчёте. Модель может явно спланировать `take_item`, `craft`, `refill` и другие существующие действия, после чего местная проверка разложит полученное. Загруженные расходники не считаются свободным запасом, если их исходный слот сам не участвует в схеме.

Обычный нативный обмен может выбросить вытесненный предмет. Поэтому перестановка сначала рассчитывается целиком и применяется без такого обмена; при отказе восстанавливаются прежние места и состояние контейнеров. Это учитывает кеши и callbacks `ItemContainer`, описанные в [исходнике игры](https://github.com/FakeFishGames/Barotrauma/blob/master/Barotrauma/BarotraumaShared/SharedSource/Items/Components/ItemContainer.cs). Защита от уборки учитывает [HumanAIController.UnequipUnnecessaryItems](https://github.com/FakeFishGames/Barotrauma/blob/master/Barotrauma/BarotraumaShared/SharedSource/Characters/AI/HumanAIController.cs). Соответствующие API сверены с локальными reference-DLL. Произвольные эффекты стороннего мода при удалении/вставке продолжают выполняться; если такой эффект удалил предмет или помешал восстановлению, ошибка сообщает это явно.

## Обзор ИИ и память

Раз в **120 секунд** при включённой непустой схеме бот получает событие `inventory review`. Обзор ждёт завершения плана, задач и опасности, соблюдает ограничения запросов и не создаёт очередь повторных обзоров. Он доступен и в режимах `events`/`order`: это отдельная возможность, включённая заданной схемой. Боты без схемы дополнительных регулярных запросов не получают.

Наблюдение содержит `inventoryLoadout` с полным набором аргументов для изменения схемы и `inventoryLoadoutStatus` с текущим статусом. ИИ может сохранить схему без изменений через `carry_on`, изменить её или запланировать недостающие запасы.

При включённой памяти схема записывается в память соответствующей кампании и восстанавливается по имени бота с новым игровым ID следующего раунда. Отключённые схемы тоже сохраняются. При отключённой памяти схема действует в текущем раунде. Повреждённый профиль не удаляет остальные воспоминания.

## Проверка

Автоматические тесты покрывают строгие аргументы, вложенные пути, конфликты правил, независимые копии, хранение по кампаниям, восстановление с новым ID, интервалы обзоров, отключение, занятость, опасность, приоритет приказов и отсутствие накопления запросов. Они не исполняют физику и callbacks запущенной игры.

Полный набор: **844 теста, 0 ошибок**; из них 122 относятся к новой схеме инвентаря. Сервер и клиент собраны для Windows, Linux и macOS: все шесть сборок завершились без предупреждений и ошибок.

Для игрового прогона:

1. Задать инструменту конкретный карман, переместить его вручную и дождаться автоматического восстановления.
2. Обменять местами два управляемых предмета при заполненных карманах; проверить, что ничего не выпало.
3. Задать стек бинтов внутри пояса, освободить один слот, проверить точное количество, недостаток места и отсутствующие запасы.
4. Задать двуручный предмет и проверить оба занятых места. Несовместимое правило для второй руки должно отклоняться.
5. Начать крафт, лечение, перенос тела, ремонт; проверить, что обслуживание ждёт окончания работы. Проверить инструмент в руке при простое и повторно при рабочей задаче.
6. Вызвать затопление/пожар, выйти наружу, снизить кислород: сортировка должна отложиться, штатная помощь — продолжиться.
7. Дождаться обзора ИИ, выключить профиль, сменить раунд и перезапустить мод. Проверить сохранение настроек и отсутствие дополнительных обзоров после отключения.
8. Для модовых контейнеров проверить ограничения отделений и восстановление после отказа вставки: предметы, заряд, работа вложенных батарей/баллонов, отображение содержимого и синхронизацию клиента.

Игровой прогон этой версии пока не выполнен.
